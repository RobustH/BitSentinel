# 前端 Worker 调度自动刷新

## 背景

前端已经可以启动、停止和手动刷新 Worker 定时调度状态，但启动后不会自动看到后端下一轮运行结果。用户需要实时知道调度是否持续工作，并在新运行产生后同步运行历史和持久化策略状态。

## 目标

- 调度运行中时，策略监控页自动刷新调度状态。
- 当后端 `runCount` 增加时，自动刷新 Worker 运行历史和持久化策略数据。
- 停止调度后自动停止轮询。
- 页面显示当前自动刷新状态，降低用户对手动刷新按钮的依赖。

## 非目标

- 不引入 React Query / SWR。
- 不做 WebSocket / SSE。
- 不做全局后台轮询，只在策略监控页挂载期间工作。
- 不改变后端调度间隔，前端轮询间隔固定为短周期状态检查。

## 交互

- 策略监控页 Worker 调度卡片展示“自动刷新：运行中/未启动”。
- 当 `schedulerStatus.running === true` 时，每 5 秒刷新调度状态。
- 如果新状态的 `runCount` 大于上一轮已同步的 `runCount`，刷新：
  - 持久化策略状态和信号。
  - Worker 运行历史。
- 当调度停止或页面卸载时清理定时器。

## 验收

- `src/App.tsx` 的定时器在 `useEffect` 中创建并清理。
- 组件不直接调用 fetch，只调用 store action。
- 自动刷新不会在未运行状态下持续轮询。
- 自动刷新检测到 `runCount` 增加时同步持久化数据和运行历史。
- 前端测试和 TypeScript 检查通过。
